Approach

Four things I do
with every agent.

01

Give agents tools, not credentials

A Model Context Protocol server exposing 28 governed tools over a relational backend, so a model acts through permissioned interfaces rather than holding database access. A fault in the model or the prompt cannot reach data the caller was never granted, because the permission check sits at the tool boundary.

MCPPermissioned toolsNo raw credentials
02

Design the tool around the question

A tool surface that mirrors the schema forces the model to rediscover the join on every call. Designing each tool around a question a business user actually asks cut the number of calls an agent needed to answer one thing.

Tool schema designFewer callsReasoning path
03

Put a gate in front of the answer

Every model response is validated before it reaches the interface, so a malformed or low confidence result is held back rather than displayed. An assistant that is confidently wrong costs more trust than one that says it is unsure, and that gate is what made a team willing to rely on generated answers day to day.

Output validationGuardrailsConfidence scoring
04

Evaluate with engineering rigor

A 70 case set with known correct answers, a pass rate reported alongside every individual failure, wired into CI so a change that moves the numbers the wrong way fails the build. I use Claude Code and Cursor daily, then read every generated change against the tests before it reaches a pull request.

Known answer setsCI regression gatesReviewed, then merged

Agentic Risk & Control Mapping

An agentic solution that reads risk, control, issue and incident data out of unstructured workbooks, then maps the relationships between them. Cut the manual effort behind that mapping by 70 percent.

  • Split the work across 3 agents so each owned one stage of extraction, matching or validation, rather than one prompt attempting the whole task.
  • Put a validation gate between stages, so a malformed result stopped at the boundary instead of being reasoned on top of by the next agent.
  • Surfaced the result through a dashboard so the risk team saw current reporting without waiting for an analyst to assemble it by hand.

RAG · Extraction

Grounded Retrieval & Extraction Service

A service that turns unstructured documents into structured records over a REST endpoint, with a confidence flag on each field so a reviewer knows what to check rather than trusting the whole output.

  • Cached embeddings so a document is never re-embedded on a repeat run, then batched the outbound calls into one request per stage instead of one per field, which is what let it run on every upload rather than on demand.
  • Structured it as stages with a validation gate between each, so a malformed or unsupported result stopped at the boundary instead of reaching the caller.
  • Covered the logic with pytest against inputs with known correct answers, so every change was measured against the same baseline rather than a fresh impression.
