Approach

01

Measure before believing

My first order book benchmark reported a throughput that was physically impossible. The optimiser had deleted a loop whose result nothing read, and the clock call cost more than the operation being timed. I now calibrate clock overhead and time blocks before trusting a per-operation number.

Clock calibrationBlock timingp50 / p90 / p99
02

Choose the layout, not the library

A flat array indexed by tick beats a balanced tree for an order book because a level lookup becomes a subtract and a load, and neighbouring levels share cache lines. The tradeoff is a bounded price range. That is a decision, not a default.

Cache localityO(1) cancelFalse sharing
03

Design for the partial failure

Services get interrupted mid run. Idempotent operations keyed on business identifiers and checkpointed recovery mean a replay produces the same result rather than duplicate records. A feed parser counts sequence gaps instead of applying across one, because a book that is quietly wrong is worse than one that stops.

IdempotencyCheckpointed recoveryGap detection

C++20 · Systems

Limit Order Book & Market Data Feed Handler

An exchange style limit order book that decodes a binary market data feed on one thread while maintaining the book on another. 7.0 ns to add an order, 4.6 ns to cancel one, 2.2 ns to read top of book.

  • Chose a flat array indexed by tick over a std::map so a level lookup is a subtract and a load, then made cancel constant time by reaching the level directly from the order id, since cancels dominate real message traffic.
  • Handed messages between threads through a lock free single producer single consumer ring, pairing release on the producer index with acquire on the consumer index, caching the opposite index to keep a contended cache line off the common path, then aligning both indices to separate cache lines.
  • Kept the book correct under a lossy feed by leaving a partial trailing message for the next read, decoding through memcpy because a socket buffer carries no alignment guarantee, then counting sequence gaps instead of applying across one.
  • Verified by 42 tests including a two thread transfer of 200,000 messages, clean under AddressSanitizer, UndefinedBehaviorSanitizer and ThreadSanitizer in CI.
